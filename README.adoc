= Extension Lister
:description: Antora extension that lists installed supplemental extensions by purpose and chassis layer.
:page-orig-author: Ryan Johnson
:page-last-edited: 2026-09-27

**Extension Lister** discovers self-register metadata from other `@antora-supplemental/*` packages and publishes:

* `/extension-lister/extensions.json`
* HTML layouts: **footer** (docs.devcentr / Valentus-style compact list), **purpose** groups, **chassis/layer** groups

== Self-register metadata API

Other extensions should export one of:

. `module.exports.registryMeta` (or `./registry` export)
. `antora-registry.md` YAML frontmatter
. `package.json#antoraSupplemental`

== Install

[source,bash]
----
pnpm add -D github:antora-supplemental/extension-lister#v0.1.0
----

== Playbook

[source,yaml]
----
antora:
  extensions:
    - require: '@antora-supplemental/extension-lister'
      layouts: [footer, purpose, layer]
      # packages: ['@antora-supplemental/link-validator', ...]  # optional explicit list
----

== DESIGN: registry filters

Catalog UIs (extension-lister locally; https://github.com/antora-supplemental/antora-extensions-registry[antora-extensions-registry] on the web) should filter listings by:

[cols="1,3"]
|===
|Filter |Meaning

|`antora.extensions`
|Pipeline / site-generator extensions (`playbook.antora.extensions`). Typically `pipeline: true`.

|`asciidoc.extensions` / Asciidoctor
|Processor extensions (`playbook.asciidoc.extensions`). Mark `asciidoctor: true`.

|Lifecycle hooks
|e.g. `sitePublished`, `contentClassified`, `documentsConverted` — from `lifecycleHooks`.

|Asciidoctor subtypes
|When `asciidoctor: true`: `processorSubtypes` such as `tree`, `inline`, `block`, `include`, `postprocessor`.

|Chassis layer
|`engine` · `chassis` · `body-kit` · `paint` · `bolt-on`.

|Purpose
|Capability tag (`link-validation`, `link-ux`, `registry`, `nav`, …).
|===

Themes (`ui.bundle`) are **not** Antora extensions; keep them in a separate catalog category.
